## 1. Did the Replication Succeed?

**Not completely.** The result is not a failure in just one direction: MSE is tied, while the two ranking-related metrics disagree.

- **MSE is nearly tied:** Baseline and RSR are identical to seven decimal places (0.0003774). After convergence, the presence or absence of a relation graph made almost no difference on this metric. Under this setup, the original paper's central claim that relational information reduces prediction error **does not hold**.
- **Baseline has higher mrrt (ranking accuracy)** (0.0488 vs. 0.0276): the model without a relation graph more often ranks the stock with the highest realized return first.
- **RSR has higher btl (simulated return)** (1.130 vs. 1.018): if the strategy is to buy the stock ranked first by the model each day, RSR produces the higher simulated return.

So whether “RSR wins” depends on the metric: the baseline wins if the goal is to rank the top stock correctly, while RSR wins on simulated trading return. This differs from the original paper's account of relational information improving performance across the board, but it is not simply a failed replication; the result depends on what is being measured.

## 2. Possible Explanations (Not Yet Tested)

These are three candidate explanations. None has been verified, so no single one is presented as the cause.

1. **Hyperparameters were not tuned:** This project fixes `seq=4, unit=32` so the baseline embedding and RSR can share the same setup. This is not a reproduction of any hyperparameter search the original paper may have performed. The paper's example commands use larger settings (for example, `seq=16, unit=64` for the Wikidata version).
2. **Only one run was performed:** Each value in Table 1 comes from a single training run with one fixed random seed. A single run cannot establish whether 50 epochs were sufficient for convergence or whether the ranking of the models is stable.
3. **The embedding was exported locally, not taken from the authors:** The official repository provides its pretrained embedding files only through an external link posted in 2019; the link has not been checked. This project avoids depending on that file and instead uses an embedding exported from its own baseline training. Its training setup may differ from the one used in the original paper.

There is currently **no evidence showing which explanation matters most**. To distinguish among them, the outstanding checks listed in `../R3_model_and_experiments/PROGRESS.md` are to rerun with another random seed and conduct a small hyperparameter search. These robustness checks were still incomplete when this R4 draft was prepared.

## 3. Comparison with the Original Paper and Comparability Limits

- This project runs only NASDAQ with the industry relation graph. The original paper also reports Wikidata relations and the NYSE market, neither of which is included here.
- The data period and two data issues identified in this project but not fully described in the original paper's documentation (the `-1234` missing-value sentinel and 156 ETFs/funds mixed into the relation graph) were handled consistently within this project (see `../R2_data_and_eda/`). It is not possible to confirm that these choices exactly match the original paper, because its preprocessing details are not documented at this level.

## 4. Limitations

- Only one ablation was run (with vs. without a relation graph); industry vs. Wikidata and NASDAQ vs. NYSE were not compared.
- The 156 ETF/fund tickers remain in the relation graph; their removal was not tested.
- Only one training run is available, so robustness has not been established.

## 5. Future Work

- Rerun with a different random seed to check whether the split between mrrt and btl was caused by a one-off random outcome.
- Conduct a small hyperparameter search, moving toward the original paper's settings, to see whether the difference is due to hyperparameters rather than relational information itself.
- If time permits, expand the ablation to Wikidata relations and the NYSE market.

(The dynamic-relation extension was explicitly dropped. Its exploration notes remain in the latter part of `../R3_model_and_experiments/PROGRESS.md` and are not part of this project's formal conclusions.)
